START HERE — Pages CMS update
==============================

What changed
-------------

Journal posts used to be full HTML files, one folder per post. From
now on they're small, plain text files (Markdown) with a bit of
structured info at the top — the CMS edits these for you, so
you'll rarely open one by hand again.

Two new things: a .pages.yml file (tells Pages CMS what a journal
post looks like — title, date, summary, video, text), and a
post/index.html page that displays whichever post you're viewing.
This replaces the old "one folder per post" approach — posts no
longer get their own folder, just one small file each.


UPLOADING THIS BATCH
---------------------

Same as always: unzip this folder, go to your repo on github.com,
"Add file" → "Upload files", drag everything in, commit.

Note: .pages.yml starts with a dot, so it might be hidden by
default in your computer's file browser. If you don't see it in
the unzipped folder, turn on "show hidden files" (Ctrl+H on
Windows/Linux Explorer, Cmd+Shift+. in Mac Finder) — it is there.

One cleanup step: your repo currently still has the OLD example
post at journal/2026-09-21/index.html (a folder). On github.com,
open that folder, delete the index.html file inside it, and it'll
clean itself up. It's been replaced by journal/2026-09-21.md in
this upload, which does the same job the new way.


USING PAGES CMS FROM NOW ON
-----------------------------

1. Go to app.pagescms.org and open this repository.
2. You should see a "Journal posts" collection — click it.
3. "Add entry" for a new post, or click an existing one to edit it.
4. Fill in: title, date, a one-line summary, and (optional) the
   full YouTube link for that week's video. Write the post itself
   in the big text box — it supports bold, italics, links, and
   photos through its toolbar.
5. Save. Pages CMS commits the file to GitHub for you — no zip,
   no upload screen, no "Add file" button. Give it a minute and
   it's live, same as before.

Photos you add through the editor land in the images/ folder
automatically — you don't need to think about where they go.


WHY POSTS ARE AT /post/?slug=2026-09-21 NOW
----------------------------------------------

Slightly different look to the old /journal/2026-09-21/ addresses.
Clean folder-style addresses need something to build a folder for
each post automatically, which needs a build step — extra moving
parts we didn't want. This way stays a plain, static site with
nothing to install or run, at the cost of a slightly less tidy
address. If that ever bothers you, it's a small upgrade later, not
a rebuild.
